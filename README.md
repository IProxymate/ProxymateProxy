# Proxymate Proxy

Расширение Chrome (Manifest V3): свои прокси-профили, автоматическая подстройка
языка и часового пояса под страну выходного узла, проверка утечек WebRTC.

## Установка

1. `chrome://extensions` → включить **Режим разработчика**.
2. **Загрузить распакованное расширение** → выбрать папку проекта.
3. Открыть карточку расширения → **Подробнее** → включить
   **«Разрешить пользовательские скрипты» / «Allow user scripts»**.

Третий шаг важен: без него `chrome.userScripts` недоступен и подмена
часового пояса переключается в запасной режим через `scripting.executeScript`,
который может не успеть отработать до скриптов страницы. Popup и раздел
«Диагностика» показывают, какой режим активен сейчас.

Сборка не нужна — чистый ES-модульный JS без зависимостей.

## Что делает

| Слой | Механизм |
|---|---|
| Маршрутизация трафика | `chrome.proxy` в режиме `fixed_servers` |
| Логин/пароль прокси | `webRequest.onAuthRequired` + `webRequestAuthProvider` |
| Часовой пояс | подмена `Date` и `Intl` в MAIN-мире на `document_start` |
| `navigator.language(s)` | подмена геттеров `Navigator.prototype` |
| HTTP `Accept-Language` | `declarativeNetRequest`, динамическое правило `modifyHeaders` |
| Координаты | обёртка над `navigator.geolocation` в MAIN-мире |
| WebRTC | `privacy.network.webRTCIPHandlingPolicy` + опция полного удаления `RTCPeerConnection` |
| Гео выходного узла | `ipwho.is` → `ipapi.co` → `ipinfo.io` (запрос идёт через сам прокси) |

Соответствие «страна → языки» и запасные зоны лежат в
[countries.js](src/lib/countries.js) — правится вручную.

## Режим подмены у профиля

У каждого профиля свой режим, он задаётся в редакторе и имеет приоритет над
тем, что «нашлось по IP»:

* **Автоматически по IP прокси** — зона, языки и координаты берутся из гео
  выходного узла при каждом подключении.
* **Задать вручную** — применяются поля профиля. Пустое поле означает, что эта
  часть не подменяется: значения из гео в него не подтягиваются.
* **Не подменять ничего** — для этого профиля сайты видят настоящие зону, язык
  и координаты. Прокси при этом работает как обычно.

Галочки в «Общих настройках» — это общий рубильник поверх режима: они могут
только запретить подмену, но не включить её там, где режим `off`.

### Геолокация

Координаты выходного узла отдаются через `navigator.geolocation` с небольшим
стабильным разбросом (~100 м), чтобы точка не была подозрительно ровной.

Запрос разрешения у пользователя сохраняется: обёртка сначала вызывает
настоящий API. Явный отказ (`PERMISSION_DENIED`) пробрасывается как есть,
а прочие сбои — недоступность сервиса геопозиции, таймаут — подменяются
нашими координатами. Объект позиции обычный, не экземпляр
`GeolocationPosition`: внутренние слоты этого класса из JS не воспроизвести.

## Контроль состояния

Расширение следит за туннелем, но **ничего не переключает само** — только
сигнализирует. Три состояния тревоги:

| Состояние | Когда возникает |
|---|---|
| `failing` | 3 отказа уровня туннеля подряд без единого успешного запроса между ними |
| `hijacked` | `chrome.proxy` перешёл под управление другого расширения или политики |
| `cleared` | наши настройки прокси сняты извне — трафик идёт напрямую |

### Блокировка трафика при перехвате

В состояниях `hijacked` и `cleared` страницы пошли бы мимо выбранного прокси,
то есть с вашим настоящим IP. Поэтому при активном профиле расширение ставит
сессионное правило `declarativeNetRequest`, которое блокирует все запросы.
Правило работает, даже когда `chrome.proxy` контролирует другое расширение.

Блокировку снимает «Отключить прокси», «Переприменить» после возврата
контроля или выключение галочки «Блокировать трафик, если прокси перехвачен
или снят» в настройках. Правило сессионное: после перезапуска браузера оно
не остаётся висеть, а состояние проверяется заново.

При `failing` блокировка не нужна: мёртвый прокси и так не пропускает трафик.

Событие о смене настроек, пришедшее во время собственной записи, не
отбрасывается, а перепроверяется по фактическому состоянию после неё.
Иначе перехват в эти доли секунды остался бы незамеченным.

Отказ одного сайта тревогу не поднимает: любой успешный запрос через туннель
обнуляет серию, поэтому «сломанный ozon при живом прокси» и «прокси лёг»
различаются надёжно. Ответы из кэша, сайты из списка обхода и локальные адреса
не считаются: они идут мимо прокси и о его живости ничего не говорят.
Перехват настроек ловится событием `chrome.proxy.settings.onChange`, без опроса
по таймеру. Разрешение `alarms` в манифесте есть, но используется только для
[проверки обновлений](#обновления) раз в сутки — к мониторингу туннеля
отношения не имеет.

Сигналы: красный `!` на значке, развёрнутое объяснение в popup с кнопками
«Переприменить» и «Отключить прокси», плюс системное уведомление (не чаще
раза в минуту, чтобы шторм ошибок не превратился в шторм уведомлений).

Собственные записи в настройки тоже поднимают `onChange`, поэтому все
применения идут через обёртку `apply()` со счётчиком глубины — иначе каждое
подключение поднимало бы ложную тревогу.

### Порядок операций и самовосстановление

Все операции, меняющие состояние и настройки браузера, выполняются строго
по очереди. Долгие сетевые запросы (определение гео, проба профиля) в очередь
не входят, поэтому «Отключить» срабатывает сразу, а не после их таймаута.

Подключение отвечает сразу после применения прокси, а страна выхода
определяется в фоне (не дольше 15 секунд на все гео-сервисы). Каждая смена
активного профиля увеличивает номер подключения. Запоздавший результат гео
или проверки сверяет этот номер и ничего не применяет, если пользователь уже
отключился или переключился.

Очередь защищена от зависания: если операция не завершилась за 15 секунд,
следующие выполняются без неё.

При каждом старте service worker'а и открытии popup или настроек настройки
прокси сверяются с активным профилем. Если профиль не выбран, а прокси
расширения стоит, он снимается. Если остался PAC от прерванной пробы, конфиг
переприменяется.

### Чего расширение не делает намеренно

Не снимает прокси при сбое и не уходит на прямое соединение. При мёртвом
прокси Chrome и так фейлит закрыто: страницы не грузятся, реальный IP никуда
не утекает. Автоматическое «восстановление» через сброс прокси превратило бы
видимую ошибку в незаметную деанонимизацию.

## Проверка прокси перед сохранением

В редакторе профиля есть «Проверить подключение»: пробный запрос уходит через
проверяемый прокси, **не разрывая текущее соединение**.

Работает это так: на время пробы ставится PAC-скрипт, который отправляет на
проверяемый прокси только один хост (`ipwho.is`), а весь остальной трафик —
туда же, куда он шёл до проверки. Прежний режим восстанавливается в `finally`
при любом исходе.

Безопасность выбрана в сторону «лучше лишний раз через прокси»: список
исключений в PAC не воспроизводится, поэтому на время пробы обходные сайты
идут через прокси, но уйти напрямую при активном профиле не могут. Даже если
service worker умрёт с установленным PAC, ветка «всё остальное» указывает на
текущий прокси, а при следующем старте браузера конфиг переприменяется.

Проба изолирована от рабочего туннеля: у неё свои учётные данные в
`onAuthRequired` (пароль проверяемого профиля, а не активного), а её ошибки
помечаются как `probe` и не увеличивают счётчик сбоев туннеля.

## Обновления

Расширение загружено «в режиме разработчика», а не из Chrome Web Store —
Chrome принципиально не даёт таким расширениям тихо обновлять себя из
внешнего источника (когда-то это работало через `update_url` в манифесте,
но для обычных пользователей давно закрыто). Поэтому автообновление здесь —
это только **проверка версии**, а установка новой — вручную:

* Раз в сутки (и один раз через 3 минуты после старта браузера)
  [update.js](src/lib/update.js) спрашивает
  `GET /repos/IProxymate/ProxymateProxy/releases/latest` и сравнивает тег
  с версией из `manifest.json`. Если вышла новая — системное уведомление и
  бейдж в шапке настроек, оба ведут на страницу релиза.
* Кнопка «Проверить обновления» в настройках — то же самое по требованию.
* Обновиться — скачать zip из релиза, распаковать поверх старой папки и
  нажать «Обновить» на карточке расширения в `chrome://extensions`.

### Как выпустить релиз

CI ([.github/workflows/release.yml](.github/workflows/release.yml)) сам
собирает zip и публикует релиз при пуше тега — вручную нужно только:

1. Поднять `version` в [manifest.json](manifest.json).
2. Закоммитить, поставить тег `vX.Y.Z` (версия без `v` должна совпадать с
   `manifest.json` — CI это проверяет и падает при расхождении) и запушить
   тег: `git push origin vX.Y.Z`.

## Резервная копия

Кнопка «Резервная копия» в шапке настроек — выгрузка профилей и настроек в JSON
и восстановление из файла. Пароли включаются по галочке и лежат в файле
открытым текстом. При восстановлении можно либо заменить всё, либо слить с
текущим списком — совпадения по `схема://логин@хост:порт` пропускаются.

## Использование

* **Popup** — список профилей (клик подключает/отключает), блок с IP, страной,
  зоной и языками, карточка текущего сайта с кнопкой «В обход» и фильтр
  профилей, который появляется, когда их больше пяти.

  Блок IP работает в обоих режимах: при выключенном прокси он показывает
  настоящий IP с пометкой, что его видят все сайты. Замер помечается признаком
  `viaProxy`, поэтому данные выходного узла никогда не выдаются за прямое
  соединение и наоборот; кэш живёт 10 минут, дальше popup перепроверяет сам.

  На значке расширения — код страны выхода (`NL`), а не безликое `ON`.
* **Настройки** — CRUD профилей, массовый импорт (`host:port`,
  `host:port:user:pass`, `socks5://user:pass@host:port`), глобальные флаги.
* **WebRTC-тест** — четыре проверки: IP/гео, ICE-кандидаты с вердиктом об
  утечке, чтение реальных значений `Date`/`Intl`/`navigator` из MAIN-мира
  активной вкладки, отражение `Accept-Language`.

  Сбор ICE-кандидатов идёт **в контексте обычной вкладки**, а не на странице
  расширения. Это принципиально: страницы `chrome-extension://` освобождены от
  mDNS-обфускации локальных адресов и показывают сырые `192.168.x.x` даже там,
  где реальный сайт увидел бы только `.local`-кандидаты. Если открытой
  http/https-вкладки нет, тест честно предупреждает, что результат завышен.

## Выбор протокола

Поле «Как соединяться с самим прокси» задаёт протокол разговора **с прокси**,
а не список сайтов, которые через него пойдут:

* **HTTP** — обычный прокси, верный выбор почти всегда. Https-сайты он
  обслуживает через `CONNECT`, никаких дополнительных настроек не нужно.
* **HTTPS** — прокси-сервер сам принимает TLS-соединения. Поддерживают единицы,
  и при неверном выборе перестаёт грузиться вообще всё.
* **SOCKS4/SOCKS5** — если так выдал провайдер прокси.

## Ограничения

* **SOCKS с авторизацией не работает.** Chrome не отдаёт расширениям
  запрос учётных данных для SOCKS — только для HTTP/HTTPS-прокси.
  Редактор профиля предупреждает об этом.
* **SOCKS4 даёт DNS-утечку.** Имена сайтов разрешает ваш DNS-провайдер, а не
  прокси. У HTTP, HTTPS и SOCKS5 имя уходит на прокси. Редактор предупреждает.
* Подмена применяется на `document_start`, то есть только к новым загрузкам.
  Вкладку, открытую до подключения прокси, надо перезагрузить — для этого в
  тесте есть кнопка «Перезагрузить вкладку и проверить».
* Настройки прокси и WebRTC ставятся в scope `regular` и **общие для всего
  браузера**, а не для отдельной вкладки. Один активный профиль за раз.
* Другое расширение с более высоким приоритетом может перехватить контроль над
  `chrome.proxy`; ошибка появится в блоке «Диагностика».
* Подмена работает на `http`/`https`-страницах. Внутренние страницы Chrome и
  страницы самого расширения показывают реальные значения — поэтому тест
  фингерпринта читает данные из вкладки, а не из своей страницы.
* Подмена часового пояса не трогает `toISOString`/`toUTCString`/`getUTC*` —
  они и должны оставаться в UTC.
* Разбор нестандартных строк даты (`"Aug 4, 2026 10:00"`) идёт через нативный
  `Date.parse` с последующим переносом в подменную зону; экзотические форматы
  могут разойтись на границе перевода часов.
* Это не полноценный антидетект: WebGL, Canvas, шрифты, `userAgentData`
  и разрешение экрана не подменяются.
* Подмена в Web Worker'ах покрывает воркеры из `blob:`. Именно их используют
  сторонние скрипты фингерпринтинга, потому что чужой домен не может запустить
  воркер с адреса страницы. Воркер пересобирается: наш код плюс исходный.
  Внутри такого воркера `self.location` указывает на новый blob.
  Воркеры с обычным URL, `data:`-воркеры и Service Worker'ы не покрываются.
* Пустые `about:blank`-фреймы подменяются при обращении к `contentWindow` или
  `contentDocument` и при вставке в документ. Функции в таком фрейме созданы в
  окне страницы, поэтому проверка `instanceof frame.Function` их выдаст.
* Пароли профилей лежат в `chrome.storage.local` открытым текстом, как и у
  других прокси-менеджеров. Расширению нужен пароль без участия пользователя
  при каждом запросе авторизации, поэтому шифрование без мастер-пароля
  защитило бы только формально.

## Структура

```
manifest.json
.github/workflows/release.yml    сборка zip и публикация релиза по тегу vX.Y.Z
src/
  background/service-worker.js   маршрутизация сообщений, авторизация прокси, восстановление состояния
  lib/
    apply.js                     применение прокси/DNR/WebRTC/инжекта
    spoof.js                     код, исполняемый в MAIN-мире страницы
    geo.js                       определение IP и гео через прокси
    countries.js                 страна → языки, страна → часовой пояс
    storage.js                   схема хранилища, разбор строк прокси
    update.js                    проверка версии через GitHub Releases
  popup/                         список профилей и статус
  options/                       редактор профилей и настройки
  leaktest/                      проверка утечек
  ui/                            общий CSS и хелперы
tests/                           node --test, без зависимостей
```

## Тесты

```
node --test "tests/*.test.mjs"
```

Зависимостей нет, нужен только Node 22 или новее. Тесты запускаются в CI
на каждый пуш, и релиз не собирается, если они упали.

* [spoof.test.mjs](tests/spoof.test.mjs) — подмена в отдельном `vm`-контексте:
  часовой пояс, `Intl`, переходы на летнее время, `Temporal.Now`, маскировка
  под нативные функции, повторное применение. Оба пути: код userscript и
  вызов в чужом окне, как для пустого фрейма.
* [spoof-dom.test.mjs](tests/spoof-dom.test.mjs) — blob-воркеры и
  `about:blank`-фреймы на минимальных заглушках DOM.
* [service-worker.test.mjs](tests/service-worker.test.mjs) — фоновый процесс
  на заглушках `chrome.*`: гонки подключения и отключения, сверка настроек,
  блокировка трафика, счётчик живости туннеля, таймауты.
